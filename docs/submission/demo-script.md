# Demo script — Context Engine for Agents

Target length: 2:45. Record in a WebMCP-capable browser and keep the cursor movements deliberate.

## 0:00–0:20 — The problem

**Voiceover:** “Websites give people pages. AI agents need knowledge about the things a business offers—and functions they can safely call. WordLift AI Audit turns any site into an evidence-backed service map.”

Show the landing page headline and briefly point to the four stages. Mention that the same compiler supports commerce, publishing, travel, finance, SaaS, and unclassified sites.

## 0:20–0:50 — An uninterrupted audit

Click one of the suggested public sites under the URL field, or type a publicly reachable site
representative of one supported archetype. Never a WordLift client other than alpina.travel.

**Voiceover:** “I enter one URL. The report opens right away and fills in while the app reads up to four useful pages and the full WordLift foundation audit runs in parallel. It classifies the business, extracts entities and language, maps expected actions, and checks the interfaces that support them — by calling them.”

Keep the progress view visible; point out the entities and the foundation score arriving before the report is complete. Do not open technical details during collection.

## 0:50–1:20 — Classification becomes a service map

Show the completed executive summary: archetype, confidence, pages analyzed, foundation score, readiness score, and three priorities.

**Voiceover:** “Classification is not a badge. It chooses the expected action model. The observed entities tell us what those actions apply to, and the evidence tells us whether a person or an agent can perform them.”

Scroll to the Context Engine.

## 1:20–1:55 — Domain graph → lexical graph → action layer

Select one domain entity. Show its source pages and aliases/topics, then observe the bound action nodes and entity chips.

**Voiceover:** “This is WordLift’s context engine: a domain graph, a lexical graph, and an action layer. Selecting an entity—such as a product, article, service, or property—shows the functions an agent needs for that exact thing. The graph also shows which human and agent interfaces provide the capability.”

Open one action drawer. Point to `applies to`, the evidence provenance, and the implementation contract.

## 1:55–2:15 — Full audit detail without interrupting the flow

Open the Full WordLift audit: it lands on the scoreboard, the dimensions that need attention are
listed first, and raw details stay folded. Expand one dimension's details and point to a quick win.

**Voiceover:** “The conversational result stays concise, but none of the WordLift audit depth is lost. Score, crawler access, quick wins, every audited dimension, findings — all there, in the order that matters, with the complete audit one click away on audit.wordlift.io.”

## 2:15–2:35 — Controlled WebMCP proof

Open the stable Alpina reference at `https://beta.audit.wordlift.io/demo/alpina`. Show the lodging entity bound to availability and run the approved read-only availability function.

**Voiceover:** “Alpina is one controlled reference adapter—not the product logic. Its existing availability function is exposed as a WebMCP tool, invoked safely, and written back as verified evidence in an immutable report revision. Nothing is booked or paid for.”

## 2:35–2:45 — Close

Show the WebMCP result or the final action state.

**Voiceover:** “Pages describe the business. WordLift connects entities, language, and actions so agents can understand what they can do—and site owners can see exactly how to get there.”

## Recording checklist

- Use one generic, non-client site for the main audit; reserve Alpina for the final controlled proof.
- Run the sidecar from the stable reference (`/demo/alpina`) so the answer shows the entity it is grounded in.
- Ensure the generic report analyzes at least three pages and shows a meaningful named entity.
- Keep the full audit collapsed until the progressive-disclosure segment.
- Show one entity selection visibly changing the highlighted action layer.
- Never claim that a declaration is a verified tool call.
- Keep the Alpina sidecar described as read-only and site-specific.
- Finish below three minutes and use only cleared brand assets and audio.
